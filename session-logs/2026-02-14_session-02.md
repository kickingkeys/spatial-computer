# Session 02 — 2026-02-14 ~19:00–21:00 EST

## Session Context

Continued from Session 01. The Stage 1 app (camera + projector + hand tracking + buttons) was built but not yet tested with Claude integration. This session focused on simplifying the interaction model and building the Claude bridge.

## What Happened

### 1. Enlarged UI for Spatial Interaction

Updated button sizes (180x40 → 340x100), fonts (1.5-2x larger), border radius, cursor sizes for gesture-friendly interaction at arm's length from the projector wall.

### 2. Simplified to "Spatial Canvas" MVP

Stripped out the button-based UI and overlay menu entirely. The new interaction model:
- **Blank canvas** projected onto the whiteboard (nothing projected by default)
- **Pinch = wake Claude** — no menus, no buttons
- Draw on the whiteboard, pinch fingers, Claude sees and responds

### 3. Built Claude Bridge (`claude_bridge.py`)

- Uses `claude -p` CLI (not Anthropic SDK — no API key configured)
- Discovered `CLAUDECODE` env var must be unset to allow nested Claude sessions
- Runs in a background thread to avoid blocking the UI
- System prompt tells Claude it's the AI brain of a spatial canvas, to generate HTML/CSS
- Uses `--allowedTools "Read,Write,Bash"` and `--output-format text`

### 4. Added HTML Preview Projection

- Chrome headless (`/Applications/Google Chrome.app/.../Google Chrome --headless --screenshot`) renders HTML to PNG
- PNG loaded into pygame surface, displayed on right half of projector
- Left half stays free for user's whiteboard drawings and status text

### 5. Fixed White-on-White Visibility Problem

**Problem**: Claude generated light-themed HTML (white/light backgrounds). Projectors can only ADD light — they cannot make the white wall darker. Light backgrounds = invisible.

**Solution**: Updated the system prompt in `claude_bridge.py` with strong dark mode instructions:
- Dark backgrounds mandatory (#000, #111)
- Bright/vivid text only (white, neon green, orange)
- Explicit instruction to override any "white background" annotations from the whiteboard
- Positioned at the very top of the prompt so Claude reads it first

### 6. Tested End-to-End (4 Pinch Cycles)

Ran the app and did 4 pinch-to-wake cycles:
1. First pinch: Claude generated HTML (initially light theme — invisible)
2. After prompt updates: Claude generated dark-themed "spatial canvas is watching" page
3. Dark page was visible on the whiteboard — confirmed working
4. Preview displayed at ~880x586 on right half of projector

### 7. Codebase Cleanup

- Removed `ui_elements.py` (dead code — not imported by anything since menu removal)
- Cleaned `config.py`: removed unused menu constants, button colors, duplicate vars, unused paths
- Updated config colors from light theme to dark projector theme (black bg, bright text)
- Updated app.py shadow color from light to dark
- Cleared `__pycache__/`
- Updated `CLAUDE.md` to reflect v0.4 MVP state

## Decisions Made

- Pinch-to-wake Claude (no buttons/menus for MVP)
- Claude CLI (`claude -p`) over Anthropic SDK (no API key needed)
- Chrome headless for HTML→PNG (zero-install, Chrome already present)
- Dark projector theme throughout (pygame + Claude HTML output)
- Preview on right half, status/text on left half
- Discussed live browser vs static PNG — decided static PNG is fine for now, may revisit
