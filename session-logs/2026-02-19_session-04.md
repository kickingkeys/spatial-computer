# Session 04 — 2026-02-19 ~research session

## What we set out to do

Find a better hardware approach. The projector was painful across three sessions — calibration breaking between hardware swaps, dark mode hacks, poor visibility, not portable. We wanted something wearable and open that could see what the user sees.

## What actually happened

### Hardware research

Evaluated two smart glasses platforms:

**RayNeo (two product lines):**
- **Air series** ($299-399): USB-C display glasses. Essentially portable monitors strapped to your face. No camera, no mic, no compute — just a screen. Could replace the projector as an output device, but doesn't solve the input problem (still need a separate camera).
- **X3 Pro** ($1099-1299): Standalone AR glasses with cameras, 6DoF tracking, hand gesture support. Full Android-based OS. More powerful but closed ecosystem, expensive, and overkill for what we need.

**Brilliant Labs Frame** ($349):
- Open source hardware and software (GitHub: brilliantlabs)
- 720p camera, mic, speaker — all in regular-looking glasses
- 640x400 micro OLED display, 16 colors, 20° FOV
- BLE 5.3 only (no WiFi)
- Python SDK (`frame-sdk`), Lua on-device runtime
- ~40-60 kBps BLE throughput (1 sec per photo transfer)

### The decision

**Frame wins.** The reasoning:

1. **Open source matters.** Full Python SDK, Lua on device, hardware schematics on GitHub. We can build exactly what we want without reverse-engineering or API limitations.

2. **Camera from POV is the right input.** Instead of a fixed overhead camera, Frame sees what you see. Look at a sketch — Claude sees the sketch. Look at a building — Claude sees the building. Natural and portable.

3. **BLE-only is fine for MVP.** We don't need video streaming. Snap a photo, send it to Claude, get a response. 1-second transfer is acceptable.

4. **Small display is a feature, not a bug.** 640x400 at 16 colors forces us to keep Frame output minimal — status, short answers, notifications. Detailed output goes to the laptop screen where it belongs. This is actually better UX than trying to cram everything into glasses.

5. **Projector is dropped entirely.** No more calibration, dark mode hacks, visibility problems, or room-specific setups. The laptop screen handles all detailed output.

### New architecture

```
Frame glasses (on your face)
  ├── 720p camera → snap photos of workspace, sketches, buildings
  ├── mic → voice commands, context
  └── display → quick status, short Claude responses

        ↕ BLE 5.3

Python host app (laptop)
  ├── frame-sdk → BLE communication
  ├── Claude bridge (claude -p CLI) → vision + text processing
  ├── Chrome headless → HTML rendering
  └── Browser window → detailed output (designs, code, etc.)
```

## What's reusable from projector sessions

- `claude_bridge.py` — Claude CLI + Chrome headless pipeline, works as-is
- Debouncing patterns — essential for any input (BLE will have latency too)
- Session logging + decision journal approach — keeps context across sessions
- The core interaction pattern: see physical things → Claude processes → show digital output

## What we're dropping

- Pygame projector display — replaced by laptop browser
- Hand tracking / MediaPipe — Frame has its own input (tap, voice)
- Calibration system — no projector = no homography needed
- Dark mode enforcement — laptop screen handles colors normally
